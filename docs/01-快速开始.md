# 01 · Quick Start / 快速开始

Deploy DeepSeek Harness (DSH) on any Docker environment.

在任意 Docker 环境部署 DeepSeek Harness（DSH）。

## 1. Prerequisites / 前置要求

- Docker Engine ≥ 20.10 (with `docker compose` v2 support)
  支持 `docker compose` v2 的 Docker Engine ≥ 20.10。
- Ability to pull `node:24-slim` (on mainland China networks, consider configuring a registry mirror accelerator; see [05-平台差异](05-平台差异.md))
  能够拉取 `node:24-slim`（国内网络建议配置 registry 镜像加速，见 [05-平台差异](05-平台差异.md)）。
- A DeepSeek API Key (or another compatible model API)
  一个 DeepSeek API Key（或其他兼容模型 API）。

## 2. Directory Structure / 目录结构

```
dsh-docker/
├── docker-compose.yml   # deployment config / 部署配置
├── Dockerfile           # base image — build it yourself or use the ghcr.io image directly / 基础镜像（可自行构建或直接用 ghcr.io 镜像）
├── entrypoint.sh        # container entrypoint / 容器入口
└── .env.example         # environment variable template / 环境变量模板
```

## 3. Installation Steps / 安装步骤

### 3.1 Clone the Repo and Configure / 拉取仓库并配置

```bash
git clone https://github.com/Steven-stack-s/dsh-docker.git
cd dsh-docker

cp .env.example .env
# edit .env; at minimum fill in: / 编辑 .env，至少填写：
#   DEEPSEEK_API_KEY=sk-你的密钥
# the rest have defaults; adjust as needed (port, data directory, resource limits, etc.) / 其余变量有默认值，可按需调整（端口、数据目录、资源限制等）
```

> `.env` is ignored by `.gitignore`, so your keys never enter git.
>
> `.env` 已被 `.gitignore` 忽略，密钥不会进入 git。

### 3.2 Start / 启动

```bash
docker compose up -d
```

On first boot, `entrypoint.sh` automatically installs `@deepseek-ai/dsh` into the volume `/opt/dsh`. On slower networks this takes a few minutes, which is normal (the compose health check already relaxes `start_period` to 300s).

首次启动时 `entrypoint.sh` 会自动把 `@deepseek-ai/dsh` 安装进卷 `/opt/dsh`，国内网络较慢，需要几分钟，属正常现象（compose 已把健康检查 `start_period` 放宽到 300s）。

### 3.3 View Startup Logs / 查看启动日志

```bash
docker logs dsh --tail 15
```

Expected output / 预期输出：

```
[entrypoint] 启动 socat 转发: 0.0.0.0:3080 -> 127.0.0.1:3081
[entrypoint] 启动 dsh web (内部 127.0.0.1:3081)
dsh web: http://127.0.0.1:3081
```

- "opening the default browser" should not appear (`--no-open` is set)
  不应出现 "opening the default browser"（已加 `--no-open`）。
- The `Connection refused` from socat right at startup is normal (dsh is not ready yet) and disappears once dsh is up
  启动瞬间 socat 的 `Connection refused` 属正常（dsh 尚未就绪），dsh 起来后消失。

## 4. Create the First Admin / 创建首个管理员

DSH's Web UI lets you create the first admin, but this operation is **loopback-only** (to prevent remote registration hijacking). Run it on the **host** (after port mapping, `127.0.0.1:3080` is the container's entry point):

DSH 的 Web 界面允许创建首个管理员，但该操作**仅限 loopback 提交**（防远程抢注）。在**宿主机**上执行（端口映射后 `127.0.0.1:3080` 即容器入口）：

```bash
curl -s -X POST http://127.0.0.1:3080/auth/bootstrap \
  -H 'Content-Type: application/json' \
  -d '{"username":"你的用户名","password":"你的密码"}'
# expected: {"ok":true,...,"user":{...}} / 期望返回 {"ok":true,...,"user":{...}}
```

Hosts without curl can use an SSH tunnel instead (see [02-认证与远程访问](02-认证与远程访问.md)).

没有 curl 的宿主机可用 SSH 隧道方式（见 [02-认证与远程访问](02-认证与远程访问.md)）。

## 5. Verification / 验证

- Open `http://<主机IP>:3080` in a browser and log in with the account you just created
  浏览器打开 `http://<主机IP>:3080`，用刚创建的账号登录。
- Go to Settings → Models and confirm the API Key is in effect
  设置 → 模型，确认 API Key 已生效。
- In `docker ps`, the `dsh` container status is healthy (being "starting" for the first few minutes after first boot is normal)
  `docker ps` 中 `dsh` 容器状态为 healthy（首次启动几分钟内为 starting 属正常）。

## 6. Stop / Uninstall / 停止 / 卸载

```bash
docker compose down          # stop and remove the container (data stays in ./dsh ./programs ./workspace) / 停止并移除容器（数据保留在 ./dsh ./programs ./workspace）
docker compose down -v       # ⚠️ also delete anonymous volumes (no named volumes are used; data lives in the mounted dirs and is unaffected) / ⚠️ 连同匿名卷一起删除（本方案未用命名卷，数据在挂载目录，不受影响）
rm -rf dsh programs workspace # permanently delete all data / 彻底删除数据
```
